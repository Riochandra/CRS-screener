Notes & method

Live data only: this screener does not contain simulated/mock scan rows. Every displayed altcoin row is fetched from the selected exchange's public market-data API at scan time. Failed API requests are excluded from the result count and reported in the status bar.

Universe: by default the scan covers the top 50 / 100 / 200 coins by market cap (CoinGecko ranking, with CoinPaprika as automatic fallback; BTC / stablecoins / wrapped and pegged tokens excluded when the toggle is on). Each coin is matched to its USDT pair on the selected exchange by ticker (1000-prefixed contracts included). Coins that are not listed on that exchange market are skipped, so the scanned count can be lower than the universe size. Switch “Rank by” to 24h volume to take the most liquid pairs on the exchange instead.

Method: each asset is compared over the exact same start/end window; manual Start/End dates and times use New York time (America/New_York, DST-aware). In Daily open mode, the start is the most recent 7:00 PM New York open and the end is the exact scan time. If the scan is before 7:00 PM NY, the start is 7:00 PM from the previous NY calendar day. RS vs BTC = Alt Return − BTC Return. RS vs ETH = Alt Return − ETH Return. Composite RS = (RS vs BTC + RS vs ETH) / 2. A positive composite means the alt outperformed the two benchmarks on average. The “Beat BTC + ETH” count requires both individual spreads to be positive. These are relative-performance measures, not predictions. Market cap is a current snapshot and 24h volume is the last 24 hours, not measured over the selected window.

Return buckets: the charts count how many scanned coins fall into each percentage-return bucket. Alt Return uses each coin’s selected-window return. Relative Strength uses the Composite RS, the average of RS vs BTC and RS vs ETH. The default bucket size is 2 percentage points; tail buckets are 3 bucket-widths wide (for example, ≤−6%, −6→−4%, …, +4→+6%, ≥+6% at 2%). The exact bucket boundaries are defined by this screener and are not claimed to be Velo’s undocumented internal boundaries.

Data: Vercel server-side proxy to public exchange market APIs plus CoinGecko’s public /coins/markets endpoint for market cap, falling back to CoinPaprika’s /tickers if CoinGecko is rate-limited or unreachable (cached for 5 minutes). Binance Spot uses api.binance.com, Binance USDT perpetuals use fapi.binance.com, and Bybit uses api.bybit.com. Historical klines and 24h ticker data are fetched live at scan time.
